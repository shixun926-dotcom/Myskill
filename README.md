## 文档清单

### 设计规范.md

**前端视觉格调设计规范（Slate 单色系）** — 适用于中后台管理系统、SaaS 控制台、数据看板等以数据为主体、信息密度高的界面。

核心主张：

> 装饰只用中性色，彩色只承载语义。视觉秩序靠明度、字重、面积建立，而不是色相。

文档包含：

| 章节 | 内容 |
|---|---|
| 0 | 文档定位、规范强度用语（必须 / 应 / 可）、四种使用场景 |
| 1 | 八条设计原则（单色系主导、语义靠小面积、不造新色等） |
| 2 | 色彩层级体系：L1 中性色 ≈90% / L2 语义色 ≈8% / L3 品牌色 ≤2% |
| 3 | 核心配色方案：Slate 11 档色阶、结构别名、语义色三件套、品牌色与替换清单 |
| 4 | 使用规则：同色透明度配方、深色渐变配方、阴影配方、明度速查 |
| 5 | 场景应用：页面层级、文字四级、按钮五型、表单、状态标签、表格、侧边栏、指标卡、图表、空状态、弹窗 |
| 6 | 风格红线：搭配黑名单、语义色边界、层级表达三手段 |
| 7 | 无障碍（WCAG 2.1）：判定标准、实测对比度、不达标替代表、双通道编码 |
| 8 | 换肤与深色模式：四令牌换主色、深浅映射表 |
| 9 | 落地资源：CSS 令牌、Tailwind 配置、JSON、命名约定 |
| 10 | 验收清单：设计评审 7 项、开发自检 8 项 |
| 附录 A–D | 最小六色子集、选色决策树、十条反模式对照、来源说明 |

## 使用方式

### 1. 作为设计依据

新增组件或页面时，按「查色板 → 查场景配方 → 过红线」三步执行：

1. 打开 `设计规范.md` 第 3 章取色值，禁止自造相近色；
2. 第 5 章按组件类型查配方（按钮、表单、标签、图表等）；
3. 第 6 章黑名单逐条比对，命中即改。

### 2. 作为开发落地

直接复制第 9.1 节的 CSS 令牌到项目 `theme.css`：

```css
:root {
  --slate-50:#f8fafc;  --slate-100:#f1f5f9; --slate-200:#e2e8f0;
  --slate-300:#cbd5e1; --slate-400:#94a3b8; --slate-500:#64748b;
  --slate-600:#475569; --slate-700:#334155; --slate-800:#1e293b;
  --slate-900:#0f172a; --slate-950:#0b1220;
}
```

接入新项目时，只需替换品牌色（第 3.6 节替换清单），中性色与语义色保持不动。

### 3. 作为评审工具

第 10 章提供两份清单：设计评审 7 项、开发自检 8 项。任一项不通过即退回，避免"看起来还行"的主观判断。

### 4. 排错

界面偏"花"时按顺序排查：彩色面积是否超过 10%（第 2.3 节）→ 是否出现第二个装饰色相 → 对比度是否达标（第 7.2 节）→ 灰度截图后层级是否仍成立。

## 维护约定

1. **新增文档**：直接放在根目录，文件名使用中文主题名，并在本文件「文档清单」中补充索引与摘要。
2. **修订规范**：改动色值或规则时，同步更新文档内所有引用位置（色值总表、场景配方、CSS 令牌、附录对照），避免多处不一致。
3. **版本标记**：每份文档开头保留版本号与日期，便于追溯。
4. **不收录的内容**：具体项目的私有信息、密钥、内部链接；规范本身应与业务解耦。
